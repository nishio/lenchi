# KJ法とLLM

川喜田二郎の **KJ法** （アイデアの付箋を空間配置→グループ化→表札→構造化）と LLM の組み合わせ。著者にとって本書の中心テーマの一つ。

## 来歴

- 『エンジニアの知的生産術』第5章「考えをまとめる」で著者が解説した手法。
- 著者はそれを電子化した [Kozaneba](../entities/Kozaneba.md) を開発・運用してきた。
- LLM 登場後、[Day6](../timeline/Day6.md)〜[Day7](../timeline/Day7.md) で「KJ法は LLM によって**進化する**のではないか」という問いが浮上。

## 何が更新されるか

- **発散の加速**: LLM がブレインストーミングで大量の候補を生成 → 付箋の数が桁違いに。
- **関連性の発見**: 付箋間の関連を LLM に提案させる。
- **表札付けの援助**: グループの抽象化・命名を LLM に補助させる。
- **講演や本に落とすときの一次元化**: KJ 法の最上位概念は抽象度が高く、聴衆には理解の土台が無いことが多い。**地図を作って観察し、説明順序を一次元化する**作業を LLM が支援できる。

## 著者の現状の運用

- [Kozaneba](../entities/Kozaneba.md) で物理的な付箋操作のメタファを電子化。
- 講演資料の準備（[Day7](../timeline/Day7.md)）で、自分の頭から出した初期構造に **LLM との対話で出てきた予期せぬ揺さぶり** を加えていくフローが効果的だと確認した。

## 未解決

- LLM 出力の「マインドマップ画像認識」の精度はまだ低い（GPT-4o では Kozaneba の解像度が読み取れない）。視覚的構造を LLM に渡すワークフローは要研究。
- KJ法 の **電子化＋LLM の組み合わせ** が、紙のKJ法の本質を保持しているか／別物になっているかは継続論点。
