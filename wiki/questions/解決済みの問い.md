### Q16. Karpathy の LLM Wiki の歴史的位置づけの検証（**解決: 概ね妥当・条件付き**）
**解決日: 2026-05-02（[Day 12 Session B](../timeline/Day12.md)）**

著者は「Karpathy の LLM Wiki は単発の発明ではなく、**LLM の賢さとコンテキスト幅の拡大により、ある種のやり方の有用性がジワジワと上がってきた** 結果の言語化」と見立てた。早期形態として **Claude Code の Skills** が同型である、という補助仮説も含めた。

[Day 12 Session B](../timeline/Day12.md) 検証結果: [ChatGPT (GPT-5系)](../entities/GPT-5系.md) によるサーベイで以下が確定（`raw/2026-05-02-Q16検証-GPT.txt`）：

- **本見立ては概ね妥当**。LLM Wiki が改善したのは LLM の内部記憶ではなく、コンテキスト維持を **外部 Markdown 知識体系の保守・検索** へ移したこと。
- **補助仮説は半分正しい**。Skills は「手続き知識」の外部化、LLM Wiki は「意味知識」の外部化で目的物が違う。ただし [段階的開示](../concepts/段階的開示.md) という設計原理は共通。Claude Code 全体（Skills + CLAUDE.md + auto memory + memory tool + filesystem access）で見ると LLM Wiki にかなり近い先行形。
- **時系列訂正**: API memory tool（2025-09-29）は Skills（2025-10-16）より前、Claude Code 内 auto memory（2026-02-05〜）は Skills より後。「memory tool」と「auto memory」を区別する必要あり。
- 反映先: [コンテキスト維持](../concepts/コンテキスト維持.md)、[第二部 導入章](../chapters/第二部-LLM_Wikiの導入.md)、新規 [段階的開示](../concepts/段階的開示.md)、新規 [RAG](../concepts/RAG.md) の Naive RAG 反省節。

残課題: GPT サーベイで参照された一次文献（Lost in the Middle、Contextual Retrieval、A-MEM、agent memory survey 等）を執筆段階で本文に組み込む（→ [Q19](未解決の問い.md#q19-外部記憶の研究系譜を本文に組み込む)）。

### Q8. プロセスログをどう本文に組み込むか（**解決**）
**解決日: 2026-05-08（[Day 16](../timeline/Day16.md)）**

[Day1〜Day10](../timeline/) の対話ログは「[創発的アプローチ](../concepts/創発的アプローチ.md) の事例」として本文に統合される予定だったが、**どの程度まで生のログを残すか** の方針が定まっていなかった。

[Day 16](../timeline/Day16.md) の著者見解で確定：

> 媒体が電子ならサイズの上限はないから **全部残すべき** だ。紙の書籍にすることがあるなら、そのタイミングでどこまで掲載するかを決めれば良い。それは今の段階で決めるべきことではない。

→ 電子（GitHub リポジトリ）では `raw/` と `timeline/` に **全量を保持する** という方針が確定。紙化時の取捨選択は将来の編集判断に委ねる。
