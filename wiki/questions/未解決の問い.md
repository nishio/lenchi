# 未解決の問い・継続課題

このプロジェクトを引き継ぐエージェントが **次に取り組むべきこと** をここに集約する。問いは大きく3層：本書の主題に関わる **理論的問い**、本書の構成に関わる **編集上の問い**、運用上の **作業課題**。

## このファイル自体の位置づけ（[Day 14](../timeline/Day14.md) で明示化）

本ファイルは LENCHI Wiki の **first-class artifact** である。3-Wiki 比較実験（[Wikiの人格化](../concepts/Wikiの人格化.md)）で確認された LENCHI の独自構造は、ingest イベントが **二層** に記録されることにある：

- **concept layer**: 新概念ページ・新エンティティページが追加される
- **question layer**（このファイル）: Q が新設・状態更新（部分対応 / 解決）される

すべての ingest / query が両層に状態変化を刻むことで、「**何が解決されたか**」「**何がまだ未決か**」を時間軸で navigable に保つ。これは「書籍プロジェクト」としての時間的な開始点と完成点を意識した設計判断であり、Karpathy の LLM Wiki や [ConnectingDots](../concepts/ConnectingDots.md) には対応する artifact がない。

### アクティブ vs アーカイブの分離（2026-05-06〜）

本ファイルには **未解決・部分対応・半解決** の問いだけを置く。**完全に解決した問い** は解決日付きで [解決済みの問い](解決済みの問い.md) に移動する。Q 番号は安定識別子として両ファイルにまたがって一意で、本ファイルに欠番（Q14・Q16・Q17）があるのは正常。

## 1. 理論的問い（本書全体の主題）

### Q1. LLM 時代に普遍／適応の境界はどこか
[2018年の知見](../entities/エンジニアの知的生産術2018.md) のうち、何が **不変で、何が再定義されるべきか**。前書きと第一章はこの問いを掲げた。各論として書き切れていないトピック（特に「やる気」「記憶」など）を実例付きで深める必要がある。

### Q2. [異知性コミュニケーション](../concepts/異知性コミュニケーション.md) は学習可能なスキルか
能力なのか才能なのか。学習可能だとして、どのような訓練・教材で身につくのか。本書でガイドラインとして提示できるレベルにあるか。

### Q3. 収束をどう支援するか
発散は LLM が得意、収束は課題（[発散と収束](../concepts/発散と収束.md)）。解候補：

1. **[KJ法とLLM](../concepts/KJ法とLLM.md)** の組み合わせ — 空間配置で人間が収束を主導
2. **[フラクタル要約](../concepts/フラクタル要約.md)** — 詳細度を選んで読む
3. **コンテキスト幅の広いモデル**（[o1 pro](../entities/o1pro.md) など）— 文脈を保持したまま長対話
4. **LLM Wiki**（[Day 12](../timeline/Day12.md) 以降の本書プロジェクト自身の運用で確認）— 概念抽出そのものが収束操作、[段階的開示](../concepts/段階的開示.md) で overview↔詳細の往復、[後段としてのWiki](../concepts/後段としてのWiki.md) が並列発散を時間をかけて吸収・収束させる。**現状もっとも有望**

それぞれを実例で示し、比較する章が未着手。LLM Wiki アプローチは本書プロジェクト自身が走る実例なので、[第二部 導入章](../chapters/第二部-LLM_Wikiの導入.md) と接続して書ける。

### Q4. [有限化と無限ネットワーク](../concepts/有限化と無限ネットワーク.md) の接続設計
書籍（有限）から、背後の [Scrapbox](../entities/Scrapbox.md)（無限）にどう橋を架けるか。本書自体がこの接続のプロトタイプになるべき。

中間層の選択肢が 2 つに分かれた：

- **A. [NISHIOアシスタント](../entities/NISHIOアシスタント.md)（カスタムGPT）** — 2024 年構築。Scrapbox を埋め込みベクトル検索する **Naive RAG 型** の対話アシスタント。発散側の価値が大きい一方、長対話で文脈を失い脱線する弱点（[コンテキスト維持](../concepts/コンテキスト維持.md)）。
- **B. Claude Code + LLM Wiki** — [Day 12](../timeline/Day12.md) 以降。**[段階的開示](../concepts/段階的開示.md) 型**の構造化された記憶＋エージェント。「特化した記憶を持って話し相手になる」という NISHIO アシスタントの中核機能を、Naive RAG ではなく Wiki 経由で実現する。収束側の支援も強い（[Q3](#q3-収束をどう支援するか)）。

A と B は **同じ機能の別実装** であり、[Day 12 Session B](../timeline/Day12.md) の「Naive RAG → Modern RAG」の構造変化が個人知識アシスタントにも当てはまる構図。本書は A も B も入口として読者に提示すべきか、書籍 → Wiki → raw → Scrapbox という多段橋を設計すべきか、未決。

### Q5. 価値あるアイデアとは何か
講演・第一章で「アイデアを思いつく」プロセスが重要であると述べたが、**価値あるアイデアの判断基準** は深掘りされていない。「実行されないアイデアに価値はなく、実現不可能なアイデアにも価値はない」という著者のメモ（[Day1](../timeline/Day1.md)）からの発展が必要。

### Q15. 「人間 × AI の協働」前提の妥当性

- 後者の世界が訪れた場合、本書は **趣味としての知的生産** に向けた本（蕎麦打ちの本のような立ち位置）として残る、というのが著者の暫定的な予想。

### Q19. 外部記憶の研究系譜を本文に組み込む
[Day 12 Session B](../timeline/Day12.md) のサーベイで参照された研究系譜は、[第二部 導入章](../chapters/第二部-LLM_Wikiの導入.md) の「[段階的開示](../concepts/段階的開示.md) と外部記憶の系譜」節の素材になる。

主要文献：

- **RAG** (Lewis et al., 2020) — 外部の非パラメトリック記憶
- **ReAct** (Yao et al., 2022) — 推論と外部行動の交互
- **Reflexion** (Shinn et al., 2023) — episodic memory としての反省
- **Generative Agents** (Park et al., 2023) — memory stream
- **MemGPT** (Packer et al., 2023) — 階層メモリ管理
- **Voyager** (Wang et al., 2023) — skill library
- **A-MEM** (2025) — Zettelkasten 的 agentic memory
- **Lost in the Middle** (Liu et al., 2023) — 長コンテキストの位置依存性能劣化
- **Contextual Retrieval** (Anthropic, 2024) — Naive RAG への反省実例
- **A Survey on the Memory Mechanism of LLM-based Agents** (2024) — 全体整理
- **[MindTrellis](../entities/MindTrellis.md)** (arXiv:2604.23129, 2026) — AI と人間が共同編集する知識グラフ。「AI 生成構造を暫定物として扱う」設計（[Day 13](../timeline/Day13.md) で取り込み）

各論文を読んで [段階的開示](../concepts/段階的開示.md) と本書の文脈に適切に位置づける作業が残っている。
